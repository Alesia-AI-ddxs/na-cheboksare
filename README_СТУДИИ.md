# «На Чебоксаре» — мобильное приложение 1.2.0

Городской квест для гостей Чебоксар. 9 точек маршрута, у каждой — рассказы героев по трём слоям
(документ / наука / предание), задание из трёх вариантов и находка в коллекцию.
Этап I «Город у воды», этап II «Купеческий город» (открывается после этапа I).
Версия 1.2.0 (таблица контента v2.9, 23.10.2026) — «волна 0» по рекомендациям владельца: скрытая «Лаборатория замеров»
(настоящие цифры телефона: 2D и 3D по бюджету 3D-модели, итог «зелёный / жёлтый / красный») и разъём «вариант Э»
(3D-сцены — отдельное приложение по ссылке). Откат на 1.1.1 — раздел «Откат на 1.1.1» в конце.
Языки (таблица контента v2.9): 22 письменных варианта в реестре; переведены 9 — ru-RU (исходник), en-GB, en-US,
de-DE, fr-FR, zh-Hans, hi-IN, tr-TR и арабский ar (справа налево, черновик ИИ). Остальные показаны как «готовится» — подробности
в разделе «Языки».

Сделано на Expo (React Native) + Expo Router. Работает на Android, iOS и в браузере. Полностью офлайн.

```bash
npm run test:publish     # тесты скриптов публикации (без настоящих магазинов)
npm run qa:plural        # «Вы нашли 1 находку / 2 находки / 5 находок / 21 находку» на всех языках
npm run qa:tofu          # нет ли букв без шрифта (квадратиков «□»), по подмножествам шрифтов
npm run qa:names         # имена (название игры, город, Волга, Сетнер) — по листу ИМЕНА
npm run qa:setner        # формат ссылки на Сетнера: start=<код>_<язык>[_<голос>], не длиннее 64
npm run qa:lab           # «Лаборатория замеров»: итог зелёный/жёлтый/красный, кадры/с, отчёт, ссылка «вариант Э» (подставные цифры)
npm run fonts:subset     # пересобрать только подмножества шрифтов (обычно их собирает генератор сам)
```

На Windows сначала дважды щёлкните `ОКНО_СТУДИИ.cmd` — откроется окно PowerShell, где прокси VPN не мешает npm.

## Первая сборка APK через EAS (по шагам)

1. `npx eas login` — откроется браузер, войдите в аккаунт Expo.
2. `npx eas init` (или `npm run eas:init`) — создаст проект в Expo и запишет `projectId` в `app.json`
   (если поле `extra.eas.projectId` уже заполнено — этот шаг уже сделан).
3. `npx eas credentials:configure-build -p android -e preview` — EAS сам создаст и сохранит ключ подписи Android.
4. `npm run eas:preview` — облачная сборка APK для теста. Ссылку на APK EAS покажет в конце.

Дальше:
- Проще всего — дважды щёлкнуть `СБОРКА_И_ВЫПУСК.cmd` и выбрать пункт меню.
- `npm run release:rustore` — сценарий `.eas/workflows/release-ru-stores.yml`: собирает APK профиля
  `production-apk` и загружает его в RuStore **черновиком** (`scripts/rustore-publish.mjs`).
  `npm run release:ru-all` — то же сразу в RuStore и AppGallery. Отправка на модерацию — только явно:
  `npx eas workflow:run .eas/workflows/release-ru-stores.yml -F stores=rustore -F submit=yes`.
- `npm run eas:release-gp` — сценарий `.eas/workflows/release-google-play.yml`: AAB профиля `production`
  → Google Play, внутреннее тестирование, черновик. Самый первый AAB Google принимает только вручную в Play Console.
- Ключи магазинов: скопируйте `.env.stores.example` → `.env.stores`, заполните, проверьте `npm run stores:doctor`.
  Для облака EAS те же имена заведите в expo.dev → проект → Environment variables (среда production, тип Secret).
- Без облака: `node scripts/rustore-publish.mjs --file app.apk --submit no` (добавьте `--dry-run`, чтобы только
  посмотреть план — ничего не отправится).
- Сборка на своём сервере без Expo — `server/README_СЕРВЕР.md`.
- Номер сборки Android (versionCode) в облаке ведёт EAS (`appVersionSource: remote`), руками не менять.
  В `app.json` стоит `android.versionCode: 4` (версия 1.2.0; у 1.1.1 был 3) — его берут сборки на своём сервере (`server/build_android.sh`).
- Веб-версия на EAS Hosting: `.eas/workflows/deploy-web.yml` — на боевой адрес (production);
  `.eas/workflows/deploy-web-preview.yml` (1.2.0) — **пробная** выкладка на постоянный адрес `https://na-cheboksare--next.expo.app`,
  боевой адрес не трогается: `npx eas workflow:run .eas/workflows/deploy-web-preview.yml`. Посмотрели — выкладываем в production.
  Важно: задача `deploy` в облаке делает обычный `expo export` без нашего шага PWA — на адресах `*.expo.app` сайт работает,
  но без офлайн-кэша (`sw.js` — незаполненный шаблон, он ничего не кэширует). Офлайн-версия — на своём сервере (`npm run web:export`).

## iPhone

**Сейчас (аккаунта Apple нет) — веб-версия как приложение (PWA).**
Сайт с игрой ставится на iPhone как обычное приложение и после первого открытия работает без интернета.
1. Выложите веб-версию на свой домен с HTTPS (`server/README_СЕРВЕР.md`, шаг 5) — или откройте готовый адрес.
2. На iPhone откройте адрес в **Safari** → кнопка «Поделиться» (квадрат со стрелкой) → **«На экран „Домой“»** → «Добавить».
3. На экране появится значок-сокол «На Чебоксаре». Он открывается без адресной строки, как приложение.
Во вкладке «О проекте» веб-версии есть та же подсказка (её не видно, когда игра уже открыта с экрана «Домой»).

**Потом — App Store (когда появится аккаунт).**
1. Оформить Apple Developer Program на ИП (платная годовая подписка, developer.apple.com). Условия оформления
   и оплаты из России перед подачей проверить на сайте Apple — здесь они **не проверены**.
2. `npx eas credentials -p ios` — войти своим Apple ID; EAS сам создаст сертификаты и профили.
3. `npm run eas:preview:ios` — тестовая сборка для своих iPhone (профиль `preview`, распространение internal;
   телефоны заранее регистрируются командой `npx eas device:create`).
4. Создать приложение в App Store Connect (bundle ID `ru.inospectrum.nacheboksare`), вписать ASC_APP_ID и
   APPLE_TEAM_ID в `.env.stores` → `npm run stores:ios-config` (запишет их в `eas.json`).
5. `npx eas build -p ios --profile production` → `npx eas submit -p ios --profile production` — сборка уходит
   в **TestFlight**; после проверки там — «Отправить на проверку» в App Store Connect.
Имя под значком на iPhone — «На Чебоксаре» (`ios.infoPlist.CFBundleDisplayName` в `app.json`).

## Как обновить тексты (заменить content.json)

1. Обновите мастер-таблицу `КОНТЕНТ_На_Чебоксаре_vX.Y_ДАТА.xlsx`.
2. Соберите JSON (и `content.json`, и языковые пакеты `locales/*.json`):
   ```bash
   python3 -I tools/content_build.py "путь/к/КОНТЕНТ_На_Чебоксаре_vX.Y.xlsx" src/content/content.json
   ```
   Генератор печатает по каждому языку «строк N из 174». Если в строке незакрытая скобка `{…}` — он остановится
   с кодом 2 и покажет, где (язык / ID строки). Исправьте в таблице и запустите снова.
   Заодно он пересобирает подмножества шрифтов письменностей (`assets/fonts/subset/`) — в них попадают ровно те буквы,
   что есть в строках таблицы. Новые иероглифы в таблице = просто запустить генератор ещё раз.
   (нужен Python 3 и пакеты: `pip install openpyxl fonttools brotli`; без шрифтов — флаг `--no-fonts`)
3. `npm run check` — скрипт покажет таблицу «точка — готова/не готова — чего не хватает».
   Недостающие тексты не ломают сборку: в приложении они помечены «готовится».
4. Если всё зелёное — `npm run eas:preview`.

Каждую строку, которую использует код, `npm run check` ищет в `locales/ru-RU.json`. Нет строки — проверка красная:
добавьте ключ в лист «Интерфейс» (на русском обязательно, на других языках — по возможности) и пересоберите.

## Где слот для Unity

Два пути 3D, оба описаны в коде; включён может быть любой из них, сейчас — ни один.

**Встроенный модуль (вариант «библиотека»).** `src/unity/UnitySlot.tsx` — компонент над виньеткой на экране точки.
Сейчас ничего не показывает (`UNITY_ENABLED = false` в `src/unity/config.ts`, в 1.2.0 так и остаётся). Здесь может
подключаться сцена Unity 6 (экспорт «как библиотека») через `@azesmway/react-native-unity`. Договор сообщений описан в файле:
приложение → Unity `{type:'showEra', pointId, era, lang, voice}` (язык и произношение — тот же выбор, что в приложении;
своей языковой системы в Unity нет), Unity → приложение `{type:'ready'}` / `{type:'sceneDone'}`.
Тексты и вопросы остаются в `content.json` — 3D-сцена их не трогает.

### Волна 0 / вариант Э (отдельное 3D-приложение по ссылке) — v1.2.0

Простыми словами: 3D-сцены живут в **отдельном приложении** (собирает подрядчик Unity). «На Чебоксаре» только открывает
его на нужной точке и передаёт язык и код прохождения. Тяжёлый 3D не утяжеляет основное приложение и не ломает его на
слабых телефонах.

**Протокол (договор между приложениями):**
- Ссылка в 3D-приложение: `<схема>://scene/<номер точки>?lang=<письменный вариант>&code=<код прохождения>`
  — пример: `nacheboksare3d://scene/2?lang=ru-RU&code=ND-9EXU`.
  - номер точки — как в `content.json` (0–8); `lang` — код языка приложения (`ru-RU`, `en-GB`, `zh-Hans`, `ar`…, см.
    `src/i18n/languages.ts`); `code` — код прохождения `ND-XXXX` (если кода ещё нет — параметра нет).
  - строит ссылку только `src/unity/appLink.ts`; проверка формата — `npm run qa:lab`.
- Обратно 3D-приложение возвращает гостя ссылкой `nacheboksare://point/<номер точки>` (схема `nacheboksare` уже есть
  в `app.json`, экран точки открывается сам).
- 3D-приложение тексты не хранит и своей языковой системы не заводит: язык берёт из `lang`, подписи — из CSV Unity,
  которые сверяются с мастер-таблицей (`check_contract_run.py`, 39/0).
- 3D-приложение должно объявить свою схему: Android — `intent-filter` (VIEW + BROWSABLE + `data android:scheme`),
  iOS — `CFBundleURLTypes`. Бюджет сцены — ≤10–20 тыс. треугольников, текстура 2K (проверяется «Лабораторией замеров»).

**Как включить (когда 3D-приложение будет готово):**
1. В `app.json` → `expo.extra.unity3dScheme` вписать схему 3D-приложения (например `nacheboksare3d`, без `://`);
   `expo.extra.unity3dStoreUrl` — страницу 3D-приложения в магазине (`https://…`), если есть.
2. Сделать **новую сборку** (EAS или свой сервер). Только сборка, обновление «по воздуху» не подойдёт: плагин
   `plugins/with-unity-3d-queries.js` дописывает в манифест Android запись `<queries>` (и схему в iOS) — без неё
   Android 11+ всегда отвечает «3D-приложение не установлено». Это не разрешение и не доступ к данным телефона.
3. На экране точки появится кнопка «Открыть в 3D» (ключ `ui.open_3d`): установлено 3D-приложение — открывает сцену точки;
   не установлено, но задан адрес магазина — открывает магазин; ни того ни другого — кнопки нет.
Сейчас обе строки пустые — кнопки нет нигде (это проверяет `npm run qa:screens`). В браузере кнопки нет никогда.

## Лаборатория замеров: как снять цифры на телефоне за 2 минуты

Зачем: решения о масштабе 3D опирались на оценки («≥30 к/с — измерить»). Лаборатория даёт **настоящие цифры**
конкретного телефона и итог по правилу владельца. Это скрытый служебный экран — гости его не видят и не находят.

1. Поставьте сборку 1.2.0 на телефон для проверки (Huawei / слабый Android — в первую очередь).
2. Закройте приложение полностью (смахните из списка недавних), закройте другие приложения, поставьте телефон на зарядку.
3. Откройте «На Чебоксаре» → вкладка **«О проекте»** → быстро коснитесь **7 раз подряд** строки
   «Версия содержания 2.9 · 23 октября 2026 г.» (под описанием проекта). Откроется «Лаборатория замеров».
   Второй способ — ссылка `nacheboksare://lab` (например, отправьте её себе в Telegram и нажмите).
4. Сразу посмотрите блок **«Холодный старт»** — это время запуска именно сейчас (поэтому шаг 2 важен).
5. Нажмите **«Запустить все замеры (около 40 с)»** и положите телефон, не трогая экран (экран сам не погаснет).
   Идут: 2D (виньетка точки + 40 движущихся элементов, 10 с), затем 3D в три ступени по 10 с:
   1 модель (~20 тыс. треугольников, текстура 2048×2048), 4 модели (~80 тыс.), 8 моделей (~160 тыс., запас).
6. Внизу — **итог цветом**: зелёный — 3D по бюджету можно делать; жёлтый — одна модель плавно, несколько с рывками,
   3D облегчённое; красный — 3D по этому бюджету тормозит, оставить 2D или уменьшить модель.
   Правило: зелёный — ступень 1 ≥ 30 к/с и ступень 2 ≥ 24 к/с; жёлтый — ступень 1 ≥ 24 к/с; иначе красный
   (сравнивается средний кадр/с; пороги — одно место в коде: `src/lab/thresholds.ts`).
7. Нажмите **«Поделиться»** (например, в Telegram — в чат студии) или «Скопировать отчёт». Отчёт — строки
   `ключ: значение`, первая строка `LAB na-cheboksare v1.2.0 <дата>`; внутри только модель телефона и цифры
   (без имени телефона, без кода прохождения). Нигде не хранится — после выхода с экрана его нет.
8. Повторите 2–3 раза и на 2–3 телефонах (флагман, средний, слабый) — решение go/no-go берите по худшему телефону
   из тех, что важны для гостей.

Что в отчёте: модель, система, ОЗУ, класс устройства (год), процессор, свободное место, экран; холодный старт
(`start_js_to_screen_ms`); 2D — средний/минимальный кадр/с, доля «тяжёлых» кадров (дольше 33 мс); 3D — видеочип, размер
холста, подготовка сцены, по каждой ступени средний/минимальный кадр/с, тяжёлые кадры, первая отрисовка, ошибки GL; итог.

**В браузере** (киоск, компьютер) лаборатория тоже работает: адрес сайта + `/lab` (например,
`https://na-cheboksare.expo.app/lab` после выкладки). Работают: 2D, 3D (WebGL), экран, язык и страна, холодный старт
(от открытия страницы). «Нет данных» в браузере: свободное место — всегда; модель и производитель — на компьютере;
ОЗУ — только в Chrome и округлённо (не больше 8 ГБ); класс устройства — нет.
Без интернета, без разрешений, ничего не сохраняет и не отправляет (правило 19 в `CLAUDE.md`).

## Языки (языковой модуль, версия 1.1.1)

Как это устроено — простыми словами:
- **Единица — языковой вариант**, а не «язык»: en-GB и en-US — разные тексты; китайских три (zh-Hans, zh-Hant, yue-Hant);
  мокшанский (mdf) и эрзянский (myv) — два разных языка; чувашский (cv) — один литературный.
- **Все слова — из мастер-таблицы.** Каждый вариант — колонка с кодом в шапке (последняя строка шапки) на листах
  «Интерфейс», «Тексты», «Легенды». Реестр вариантов — лист «ЯЗЫКИ», передача имён — «ИМЕНА», кто вычитал — «ВЫЧИТКА».
- **Пустая ячейка — не ошибка.** Приложение покажет строку по «лестнице»: точный вариант → старший → en-GB → ru-RU.
  Вариант совсем без перевода виден в списке с меткой «готовится» и пока не выбирается.
- **Черновик честно помечен.** Если в листе «ЯЗЫКИ» у варианта «Статус текста» = ЧЕРНОВИК, на экране выбора языка и в прологе
  под названием языка мелко написано «черновик — вычитка носителем впереди». После вычитки поставьте статус «ВЫЧИТАНО НОСИТЕЛЕМ» /
  «ПРИНЯТО» и пересоберите — метка уйдёт сама.
- **Предлагаем (1.1.1):** вверху экрана выбора — блок «Предлагаем»: язык телефона и языки страны, указанной в настройках
  телефона (колонка «Страны (ISO 3166-1)» листа ЯЗЫКИ = поле `regions` в `languages.ts`; `npm run check` сверяет).
  Страна берётся только из настроек телефона (`expo-localization` → `regionCode`): без геолокации, без интернета, без
  разрешений. Предлагаются только переведённые варианты (готовые и черновики), без повторов. Пример: телефон на английском,
  страна Китай → English (UK) и 中文（简体）; страна Саудовская Аравия → English (UK) и العربية; Россия → Русский
  (чувашский и другие языки России появятся в блоке, когда у них будет перевод).
  **Следующий шаг (не сделан):** предлагать язык территории по внешнему сервису (API) или помнить язык в аккаунте
  пользователя — сейчас аккаунтов нет, поэтому только настройки телефона.
- **Выбор языка:** при первом запуске приложение само предлагает язык телефона (браузера) — одна кнопка «Продолжить»;
  все языки написаны на самих себе, без флагов. Где произношений несколько (английский, немецкий, французский, китайский,
  арабский), вторым шагом выбирается произношение. Сменить язык — «О проекте» → «Выберите язык» или карточка языка в прологе.
  Выбор запоминается на устройстве.
- **Справа налево (арабский, фарси):** в браузере страница зеркалится сразу; на телефоне — после короткого перезапуска
  (экран «приложение перезапустится» → кнопка).
- **Шрифты:** латиница и кириллица — фирменные Prata + PT Sans (в них есть все буквы языков России); китайский, хинди/маратхи,
  арабский/фарси — Noto, грузится только шрифт выбранного письма. С 1.1.1 это **подмножества**: в шрифте только буквы из
  строк таблицы (+ цифры, латиница, знаки; у арабского и деванагари — весь блок письма, т.к. месяцы в датах пишет система).
  Китайский — ≈0,3 МБ вместо ≈10 МБ; все шрифты письменностей вместе — ≈0,9 МБ вместо ≈25 МБ. Традиционный китайский и
  кантонский пока без шрифта (нет текстов, «готовится»); появятся тексты — генератор сам создаст подмножество.
  В веб-версии все шрифты кэшируются заранее — любой язык работает без интернета с первого открытия.
- **Имена — по листу ИМЕНА:** название игры (`ui.title`, прописными), Чебоксары, Волга, Сетнер. Транслит «Na Cheboksare»
  запрещён. Проверка — `npm run qa:names`. Пустые клетки ИМЕНА для языков России — спросить носителя.
- **Сетнер и Unity получают язык.** Telegram передаёт боту только значение `start`, поэтому язык едет внутри него:
  `https://t.me/Setner_Cheboksary_bot?start=<код>_<письменный>` или, если произношение отличается от письменного варианта,
  `…?start=<код>_<письменный>_<голосовой>` (примеры: `ND-9EXU_ru-RU`, `ND-9EXU_ar_ar-EG`, `ND-9EXU_en-GB_en-IE`,
  `ND-9EXU_zh-Hans_yue-CN`). Только латиница, цифры, `_` и `-`, не длиннее 64; не помещается — сначала убирается голос,
  потом язык, код прохождения остаётся всегда. **Боту:** `/start` → разделить по «_»: `[код, письменный?, голосовой?]`;
  нет голоса — голос = письменный вариант. Строит ссылку только `src/setnerLink.ts`; проверка — `npm run qa:setner`.
  Сообщение для Unity `showEra` — с полями `lang` и `voice`.
- **Версия содержания** на вкладке «О проекте» — на языке гостя (`ui.content_version`, номер и дата — из листа «Как устроено»).

### Как добавить язык (пример: казахский kk)

1. Лист **«ЯЗЫКИ»**: строка «письменный» — код (по BCP-47: `kk`), язык по-русски, эндоним («Қазақша»), письменность,
   направление, шрифт, фолбэк, статус текста «ЧЕРНОВИК», тест-строка со всеми особыми буквами (ә ғ қ ң ө ұ ү һ і).
   Ниже — строки «голосовой» для каждого произношения. Колонка «Страны (ISO 3166-1)» — коды стран через запятую.
   В листе **«ИМЕНА»** — колонка с кодом: название игры, Чебоксары, Волга, Сетнер.
2. Листы **«Интерфейс», «Тексты», «Легенды»**: новая колонка, в шапке последней строкой — код `kk`. Заполнить переводы
   (можно частично — пустое возьмётся по лестнице).
3. Файл **`src/i18n/languages.ts`**: запись варианта (код, эндоним, письмо, группа, шрифт, фолбэк, голоса, `regions` — как в
   колонке «Страны») — по образцу соседних. Если письмо новое (например, грузинское) — добавить шрифт Noto в
   `tools/font_subset.py` (SOURCES/EXTRA), `tools/tofu_check.py` (FULL) и тип `FontFamily` в `languages.ts`.
4. Собрать: `python3 -I tools/content_build.py "<таблица.xlsx>" src/content/content.json` → `npm run check` →
   `npm run qa:tofu` → `npm run qa:names` → `npm run web:export` → `npm run qa:screens`.
Всё. Код экранов трогать не нужно.

### Как добавить озвучку

1. Файлы: `audio/<голос>/<ID строки>.mp3` на сервере пакетов (адрес — `app.json → extra.langPackBaseUrl`).
   `<голос>` — код произношения (`en-GB`, `yue-CN`) или фирменный голос на языке: `<brandId>@<код>` —
   например `audio/aleksandr@en-GB/T06_EFREMOV_NARR.mp3` (фирменные голоса: aleksandr, olesya, mulyaev).
2. Манифест `assets/audio/manifest.json`: в `voices` добавить ключ голоса (`"aleksandr@en-GB"`) со списком `ids`
   озвученных строк, источником (`elevenlabs` / `azure` / `alibaba` / `narrator`) и тем, кто подтвердил звучание (`approvedBy`).
3. Пересобрать. Кнопка «Послушать» появится только у озвученных строк; если нужного голоса нет, звучит ближайший
   по лестнице (фирменный голос → обычный голос наречия → старший). В веб-версии звук играет сразу; в приложении
   для телефона проигрыватель (expo-audio) подключается на этапе 3 озвучки — до этого кнопка на телефоне скрыта.
