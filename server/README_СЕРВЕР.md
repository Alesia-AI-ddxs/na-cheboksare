# Свой сервер для «На Чебоксаре»: сборка Android без облака Expo + веб-версия

Всё в этой папке работает на обычном Linux-сервере (Ubuntu 22.04 или 24.04), **без Docker и без облака Expo**.
Сервер делает две вещи:

1. **Собирает Android-приложение** (APK для RuStore/AppGallery, AAB для Google Play), подписывает его вашим ключом.
2. **Раздаёт веб-версию** (PWA) — её ставят на iPhone через «Поделиться → На экран „Домой“», работает без интернета.

| Файл | Что делает |
|---|---|
| `setup_build_server.sh` | Один раз: ставит Node.js 22, Java 17, Android SDK, nginx |
| `make_keystore.sh` | Один раз: создаёт ключ подписи Android и файл `.env.signing` с паролем |
| `build_android.sh` | Каждый выпуск: собирает APK или AAB в `server/out/` |
| `patch-signing.mjs` | Вызывается сборкой сама: вписывает подпись и номер сборки в проект Android |
| `deploy_web.sh` | Каждый выпуск сайта: собирает веб-версию и кладёт её в папку nginx |
| `nginx-na-cheboksare.conf` | Пример настройки nginx (корень домена и адрес `/turizm/app/`) |

---

## Шаг 1. Скопировать проект на сервер

Вариант А — через git (если вы добавили удалённый репозиторий):

```bash
git clone <адрес-вашего-репозитория> /opt/na-cheboksare
cd /opt/na-cheboksare
```

Вариант Б — архивом: распакуйте zip проекта в `/opt/na-cheboksare` (папки `node_modules`, `android`, `dist*` копировать не нужно).

## Шаг 2. Подготовить сервер (один раз, ~10–20 минут)

```bash
cd /opt/na-cheboksare
sudo bash server/setup_build_server.sh
```

После этого **откройте новое окно терминала** (чтобы подхватились переменные Android).
Что именно ставится и какие версии Android — написано в начале самого скрипта. Запускать повторно можно.

## Шаг 3. Ключ подписи Android (один раз на всю жизнь приложения)

```bash
bash server/make_keystore.sh
```

Появятся `secrets/na-cheboksare-release.jks` (ключ) и `.env.signing` (пароль). Оба в git **не попадают**.

> **Сразу сделайте резервную копию** этих двух файлов (флешка + надёжное облако).
> Если ключ потерять, выпустить обновление приложения в RuStore/AppGallery будет **невозможно**.

Скрипт также печатает отпечаток SHA-256 — его иногда просят магазины, это не секрет.

## Шаг 4. Собрать APK или AAB

```bash
bash server/build_android.sh apk          # APK — RuStore, AppGallery, установка напрямую
bash server/build_android.sh aab          # AAB — Google Play
```

Готовый файл: **`server/out/na-cheboksare-<версия>-production-<дата>.apk`** (рядом — `.sha256` с контрольной суммой).
Первая сборка идёт долго (скачиваются Gradle и библиотеки, 10–30 минут), следующие — быстрее.

Номер сборки (versionCode) для магазинов ставится сам из даты и часа (например `26102215`) — он всегда растёт.
Свой номер: `ANDROID_VERSION_CODE=5 bash server/build_android.sh apk`.

> Если параллельно собираете и в облаке EAS — у EAS свой счётчик номеров. Магазин примет файл только с номером
> **больше** прошлого. Проще выбрать один путь сборки. Выровнять EAS можно командой `npx eas build:version:set`.

Загрузить в RuStore черновиком (ключи — в `.env.stores`, см. `.env.stores.example` в корне проекта):

```bash
node scripts/rustore-publish.mjs --file server/out/<файл>.apk --submit no
node scripts/appgallery-publish.mjs --file server/out/<файл>.apk --submit no
```

## Шаг 5. Веб-версия (PWA) на своём домене

### Вариант А — приложение в корне домена: `https://<домен>/`

```bash
sudo bash server/deploy_web.sh / /var/www/na-cheboksare
```

### Вариант Б — приложение по адресу `https://<домен>/turizm/app/`

```bash
sudo bash server/deploy_web.sh /turizm/app /var/www/turizm/turizm/app
```

(папка повторяет адрес — так nginx находит файлы без хитростей)

### Настроить nginx (один раз)

```bash
sudo cp server/nginx-na-cheboksare.conf /etc/nginx/sites-available/na-cheboksare.conf
sudo nano /etc/nginx/sites-available/na-cheboksare.conf      # вписать свой домен вместо example.ru
sudo ln -s /etc/nginx/sites-available/na-cheboksare.conf /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

**HTTPS обязателен** — без него iPhone не включит работу без интернета:

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d <домен>
```

Проверка: откройте `https://<домен>/` на iPhone в Safari → «Поделиться» → «На экран „Домой“».
Значок «На Чебоксаре» появится на экране; после первого открытия игра работает и в режиме полёта.

## Как обновлять

```bash
cd /opt/na-cheboksare
git pull                              # или распакуйте новый zip поверх (secrets/ и .env.* не трогайте)
bash server/build_android.sh apk      # новое приложение
sudo bash server/deploy_web.sh / /var/www/na-cheboksare   # новый сайт
```

Телефоны с установленной веб-версией получат обновление сами при следующем открытии с интернетом.

## Сколько людей выдержит

- Сайт — это **готовые файлы**, сервер ничего не «считает». nginx на 1 vCPU / 1 ГБ памяти раздаёт такие файлы
  тысячам людей одновременно; 10 000 одновременных посетителей для процессора — обычная нагрузка.
- Узкое место — **канал связи**, а не процессор. Первое открытие скачивает всё приложение один раз:
  **≈1,4 МБ по сети** (3,6 МБ без сжатия; измерено на сборке 1.0.0). Пример расчёта: 10 000 человек открыли
  сайт впервые в одну и ту же минуту = ≈14 ГБ; канал 100 Мбит/с отдаст это примерно за 20 минут, 1 Гбит/с — за 2 минуты.
  Повторные открытия почти ничего не качают — всё уже лежит в телефоне.
- Если ждёте всплеск (городской праздник, реклама) — поставьте перед сервером бесплатный CDN, например **Cloudflare**
  (тариф Free): он раздаст файлы из своих серверов, ваш сервер почти не нагрузится. В настройках nginx уже
  выставлены правильные заголовки кэша (скрипты — на год, страницы и `sw.js` — без кэша).
- Само приложение **полностью офлайн**. Единственное, что живёт в интернете, — **Telegram-бот** (Сетнер);
  его доступность от этого сервера не зависит.

## Если что-то пошло не так

| Сообщение | Что делать |
|---|---|
| `не найден Android SDK` | Не выполнен шаг 2 или не открыт новый терминал |
| `нет файла .env.signing` | Не выполнен шаг 3 |
| `файл подписан отладочным ключом` | Проверьте `.env.signing`: путь к ключу и пароль |
| Сайт открывается, но без интернета не работает | Нет HTTPS (шаг 5): без него телефон не включает офлайн-режим |
| `в dist нет sw.js` | Запускайте `deploy_web.sh`, а не `npx expo export` напрямую |
